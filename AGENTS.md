# Паспорт сервиса Ноготочки

## Цель
Учебный сервис онлайн-записи в студию маникюра и бровей. Сервис проводит клиента от регистрации до записи на свободное время и даёт администратору инструменты управления расписанием и каталогом.

## Аудитория
- Клиенты студии, которые выбирают услугу, мастера, дату и время.
- Администратор студии, который ведёт услуги, мастеров, блокировки и записи.
- Наставник, проверяющий проектную работу и сценарии безопасности.

## Роли и доступ
- `client`: регистрация, вход, создание записи и просмотр только собственных записей.
- `admin`: клиентские возможности плюс защищённые `/admin`, `/admin/appointment`, `/admin/block` и `/admin/catalog`.
- Клиент не видит ссылку на админку; прямой запрос возвращает `403`. Чужая запись возвращает `404`.

## Основные сценарии
1. Регистрация или вход по email и паролю; опционально вход через Яндекс OAuth.
2. Выбор активной услуги, активного мастера и даты.
3. Расчёт свободных слотов по графику, длительности услуги, активным записям и блокировкам.
4. Создание записи с повторной серверной проверкой доступности.
5. Просмотр записи в кабинете клиента после обновления или повторного входа.
6. Просмотр, перенос и отмена записи администратором.
7. Блокировка времени мастера и управление активностью услуг и мастеров.

## Функции клиента
- Регистрация, вход, выход и личный кабинет.
- Просмотр витрины активных услуг и только фактически доступных слотов.
- Создание записи и просмотр её статуса.
- Отсутствие доступа к данным других клиентов и административным маршрутам.

## Функции администратора
- Просмотр всех записей.
- Перенос существующей записи без создания дубликата.
- Отмена через смену статуса; освободившееся время снова доступно.
- Создание блокировки времени мастера.
- Добавление, редактирование и отключение услуг и мастеров.
- Старые записи сохраняют снимок названия услуги и мастера после отключения справочника.

## Данные
Таблицы: `users`, `sessions`, `oauth_states`, `services`, `masters`, `schedules`, `blocks`, `appointments`. В production используется Supabase PostgreSQL, локально и в тестах — SQLite. Миграция старой схемы выполняется идемпотентно при запуске.

## Ограничения
- Учебный сервис не предназначен для реальных персональных данных и платежей.
- Базовый график: понедельник–суббота, 10:00–19:00; шаг слотов 30 минут.
- Расписание меняется через базу или миграцию; отдельного экрана редактирования недельного графика нет.
- Время хранится как локальное студийное время без преобразования часовых поясов.

## Риски и защита
- Гонка за слот: на PostgreSQL используется транзакционная advisory-блокировка на мастера и дату, затем доступность проверяется повторно.
- Пересечения сравниваются с учётом длительности услуги, а не только одинакового времени начала.
- Секреты читаются из переменных окружения; `.env` не хранится в репозитории.
- Пароли хешируются PBKDF2-HMAC-SHA256 с индивидуальной солью; токены сессий и OAuth state хранятся в виде SHA-256.
- SQL выполняется с параметрами; пользовательские значения экранируются при выводе.

## Проверки
Команда: `python -m unittest discover -s tests -v`. Набор покрывает успешную запись, сохранение, конфликт и пересечение слотов, конец рабочего дня, блокировку, чужую запись, запрет админки, отмену, перенос, отключённый каталог и повторный OAuth-вход.

## Публикация
GitHub → Vercel, база Supabase PostgreSQL. `DATABASE_URL` и остальные секреты задаются только в Vercel Environment Variables. Схема и миграции находятся в `schema.sql` и `migrations/`.
